# 아키텍처

이 문서는 라우터가 요청 하나를 받아 모델 하나를 고르기까지의 경로와, 그 경로가 어떤 성질을 보장하도록 설계됐는지를 설명합니다. 왜 이 구조를 골랐는지는 [decisions.md](decisions.md)가 다룹니다.

## 전체 흐름

라우터는 배치 단위로 동작합니다. 입력은 문항들의 프롬프트 본문, 실행 등급(fast·balanced·premium), 그리고 모델별 단가가 담긴 공식 비용 정책이 전부입니다. 문항 ID·입력 순서·split·과제명은 읽지 않습니다.

```
프롬프트 배치
  → 특징 추출 (문항당 8,259차원)
  → 점수·비용 예측 (dual ridge, 모델 3종 × [점수, 로그 비용])
  → 소진 가드 (특정 패턴에서 추론 모델 승급 유인 차단)
  → 비관 쐐기 (예측 비용 × exp(β·σ))
  → 예산 지갑 (한도 × margin, premium은 배치 규모 분기)
  → 볼록껍질 그리디 배낭 (승급 증분을 효율 순으로 구매)
  → 문항별 모델 배정
```

모든 문항의 배정은 어떤 모델도 호출되기 전에 확정됩니다. 싼 모델을 돌려보고 결과를 본 뒤 승급하는 캐스케이드는 규칙이 금지하며, 이 코드에는 그런 경로 자체가 없습니다.

## 계층과 파일

| 계층 | 파일 | 역할 |
|---|---|---|
| 진입점 | `src/ossp_router/heuristic.py` → `learned_router.py` | 입력 파싱, 등급별 설정 적용, 배정 출력 |
| 특징 | `src/ossp_router/learned_features.py` | 수치 특징 67개 + crc32 해시 n-gram 8,192칸. 표준 라이브러리만 사용 |
| 예측 | `learned_router.py` 안의 선형 평가 | 아티팩트의 가중치로 6개 헤드(모델 3종 × 점수·로그 비용)를 내적 한 번에 계산 |
| 배분 | `learned_router.py` 안의 배낭 | 승급 증분을 점수 이득 ÷ 비용 순으로 정렬해 지갑이 허락하는 만큼 구매 |
| 학습 | `analysis/train_linear.py` (+ `os2_features.py`, `os2_policy.py`) | 공개 train 1,760문항으로 dual ridge 폐형해를 풀어 아티팩트 생성. numpy 필요, 이미지에는 들어가지 않음 |

학습 측과 런타임 측은 특징 추출과 배분을 각각 따로 구현합니다. 두 구현이 비트 단위로 같은지는 `tests/test_feature_parity.py`가 공개 train 전량으로 검사하고, 학습 스크립트도 종료 직전에 런타임 구현으로 같은 문항을 다시 예측해 최대 오차가 1e-9를 넘으면 실패로 중단합니다.

## 아티팩트

학습 결과는 `src/ossp_router/resources/learned-router.v1.json` 하나(1.11 MB)입니다.

- `weights` — 모델·헤드별 계수 8,259개 (수치 67 + 해시 8,192)
- `cost_smear`, `cost_sigma` — 로그 비용 잔차의 보정·산포. 비관 쐐기 `exp(β·σ)`의 재료
- `tier_config` — 등급별 β와 margin. premium은 `margin_deep`(1.08)과 `deep_min_episodes`(800)를 추가로 가짐: 배치 문항 수가 800 이상이면 margin_deep을, 미만이면 기본 margin을 씁니다. 예산 한도가 문항 수의 함수로 정의되므로 이 분기는 규칙 안이며, 배치가 작아지는 방향의 실패는 자동으로 보수 모드가 됩니다

## 결정성 보장

같은 입력이면 언제 어디서 돌려도 같은 출력이 나와야 합니다. 세 층위로 보장하고 검사합니다.

1. **반복 실행** — 같은 배치를 다시 돌리면 출력 바이트까지 일치합니다. 난수·시각·환경 의존이 없습니다.
2. **순서·ID 불변** — 문항 순서를 섞거나 episode_id를 바꿔도 배정이 변하지 않습니다. 배낭의 동률 처리를 문항 위치가 아니라 예측값 튜플로 끊었기 때문입니다.
3. **학습·런타임 동치** — 캘리브레이션 시점의 배분과 제출 런타임의 배분이 전 문항에서 같음을 전수 비교했습니다.

## 패키징 경계

이미지에 무엇이 실리는지는 `.dockerignore`가 전부 거부한 뒤 필요한 파일만 다시 허용하는 화이트리스트로 정합니다. 이 목록에서 파일 하나가 빠져 세 등급 모두 0점이 될 뻔한 사고가 있었고, 그 뒤로 `tests/test_image_packaging.py`가 진입점에서 도달 가능한 모듈을 정적으로 추적해 누락을 잡습니다. 컨테이너는 네트워크 없이 실행되며(`tools/check_runtime.py`로 확인) 런타임은 표준 라이브러리 외에 아무것도 import하지 않습니다.
