# 로드맵

대회 제출 이후 이 저장소가 갈 수 있는 방향입니다. 순서는 우선순위이며, 각 항목은 대회 기간의 실측에서 나온 미해결 문제와 잇닿아 있습니다.

## 1. 예산 제약 라우팅 라이브러리로의 분리

지금의 런타임은 이 대회의 모델 3종·등급 3종에 배선돼 있지만, 핵심 구조 — 선형 예측, 비관 쐐기, margin 지갑, 볼록껍질 배낭 — 는 후보 모델이 N개인 일반 문제에 그대로 확장됩니다. 정책 스키마를 일반화해 표준 라이브러리 전용 패키지로 분리하는 것이 첫 목표입니다. 총비용 초과가 부분 감점이 아니라 실격인 환경(고정 예산의 배치 API 운영 등)에서 재사용 가치가 있습니다.

## 2. 라벨 효율

공개 라벨 1,760개는 이 프로젝트의 모든 기각 결정에 그림자를 드리웠습니다. 소형 인코더 임베딩처럼 신호가 실재하는데 점수로 환산되지 않은 사례가 여럿입니다. 어떤 문항의 라벨이 배분 결정을 가장 많이 바꾸는지로 라벨링 우선순위를 정하는 능동 라벨링이 다음 실험 축입니다.

## 3. 컨텍스트 소진 비용의 예측

비용 분포의 꼬리 — 출력이 컨텍스트 한도까지 자라 비용이 천 배 넘게 뛰는 문항 — 는 프롬프트 본문만으로 예측되지 않았고, 현재는 어휘 가드와 비관 쐐기라는 정책으로 막고 있습니다. 이 문항들을 사전에 식별하는 것은 열린 문제로 남깁니다. 실패한 접근(분위수 상한, 유형별 분산, 소진 확률 혼합)의 기록이 [decisions.md](decisions.md)에 있으므로, 같은 길을 다시 걷지 않아도 됩니다.

## 4. 재현 파이프라인의 공개 범위

현재 main 트리는 제출 런타임과 최종 학습기만 담고, 실험 하네스와 게이트 원장은 git 히스토리와 별도 문서 저장소에 있습니다. 심사·연구 재현 수요가 있으면 fold 정의와 게이트 러너를 research 디렉토리로 복원하는 것을 검토합니다.

## 5. 커뮤니티

이슈 템플릿(버그·개선 제안·질문)과 PR 템플릿을 열어뒀습니다. 개선 제안은 이 저장소의 판정 절차 — 사전 등록 게이트, train 전용 선택 — 를 그대로 적용해 평가합니다. 절차는 [decisions.md](decisions.md)에 있습니다.
