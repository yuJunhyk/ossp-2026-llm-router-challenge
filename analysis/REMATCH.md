# 예측기 재대결 기록 (v1.3 채택 근거)

날짜: 2026-08-13 · 스크립트: `analysis/rematch.py` · 보고서: `build/rematch-report.json`

## 배경

v1.2까지의 예측기 선택(ens 채택, 앙상블 가중 0.5)·배포 버퍼는 공개 Dev
채점이 의사결정에 반복 개입해 낙관 편향이 있었다. 독립 재구현 세션과의
교차 검증에서 같은 결론이 나와, Dev를 전혀 쓰지 않는 재대결로 배포
예측기를 다시 선택했다.

## 프로토콜 (train 1,760문항 전용, Dev 미접촉)

- **fold**: 템플릿 그룹 단위 5-fold × fold-seed {11, 22, 33} = 15 fold.
  정규화 25자 접두사를 공유하는 문항(2개 이상, 총 756문항)은 같은 fold에
  묶어 순번 modulo 분할의 템플릿 누수를 차단.
- **배분**: `analysis/os2_policy.allocate` (볼록껍질 그리디) — 두 후보 동일.
- **제약**: tier별 (β, margin)은 ① 15 fold 전부 실현 예산비 ≤ 한도 ×
  {fast 0.90, balanced 0.95, premium 0.95}, ② 유형 편향 부분집합 9종
  (한국어/영어/단문/장문/객관식/비객관식/수학/비수학/코드) OOF 실현
  예산비 ≤ 한도 × 0.98. 만족 설정 중 CV 평균 점수 최대를 채택.
- **후보 내부 변형도 같은 기준으로 재선택** (v1.2 값 이어받기 금지):
  선형 λ ∈ {1, 3, 10}, ens 앙상블 가중 w ∈ {0, 0.25, 0.5, 0.75, 1},
  GBM 라운드는 그룹 OOF MSE로 타깃별 선택 (격자 100~1600).

## 판정과 정직한 주석

- 1~3위 차이(0.0013)는 CV 노이즈 범위 안이라 통계적으로 결정적이지 않다.
  **사전 등록한 규칙**(가중 CV 승자 채택, 동률이면 선형 — dev-clean 계보와
  순수 stdlib 레이턴시 우위)에 따라 linear(λ=10)를 채택했다.
- v1.2의 실제 구성(ens w=0.5)이 깨끗한 프로토콜에서 5위로 떨어진 것은
  Dev 재사용이 선택을 왜곡했다는 감사 결론의 실증이다.
- 이 표의 수치는 그룹-fold CV 추정치로, 공개 Dev 점수와 직접 비교할 수
  없다 (분포·누수 조건이 다름).

## 후속 조치

- 최종 학습·아티팩트: `analysis/train_linear.py` →
  `src/ossp_router/resources/learned-router.v1.json` (1.11 MB), 런타임 표본
  대조 최대 오차 1.8e-15.
- 배분 tie-break를 문항 위치 인덱스에서 예측값 튜플(내용 유도)로 교체 —
  ID·순서 셔플 점검 대응. 캘리브레이션 시점 배분과의 동치성을 fitted×3 +
  15 fold×3 = 48건 전수 비교로 확인 (불일치 0건).
- 컨테이너 재검증: 3-tier PASS, tier당 5.4초 (ens 대비 2.6배 개선),
  이미지 내 필수 파일 존재 확인.
