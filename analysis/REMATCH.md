# 예측기 재대결 기록 (v1.3 채택 근거)

날짜: 2026-08-13 · 스크립트: `analysis/rematch.py` · 보고서: `build/rematch-report.json`

## 배경

v1.2까지의 예측기 선택(ens 채택, 앙상블 가중 0.5)·배포 버퍼는 공개 Dev
채점이 의사결정에 반복 개입해 낙관 편향이 있었다. 독립 재구현 세션과의
교차 검증에서 같은 결론이 나와, Dev를 전혀 쓰지 않는 재대결로 배포
예측기를 다시 선택했다.

## 프로토콜 (train 1,760문항 전용, Dev 미접촉)

- **fold**: 템플릿 그룹 단위 5-fold × fold-seed {11, 22, 33} = 15 fold.
  정규화 25자 접두사를 공유하는 문항(2개 이상, 총 756문항)은 같은 fold에
  묶어 순번 modulo 분할의 템플릿 누수를 차단.
- **배분**: `analysis/os2_policy.allocate` (볼록껍질 그리디) — 두 후보 동일.
- **제약**: tier별 (β, margin)은 ① 15 fold 전부 실현 예산비 ≤ 한도 ×
  {fast 0.90, balanced 0.95, premium 0.95}, ② 유형 편향 부분집합 9종
  (한국어/영어/단문/장문/객관식/비객관식/수학/비수학/코드) OOF 실현
  예산비 ≤ 한도 × 0.98. 만족 설정 중 CV 평균 점수 최대를 채택.
- **후보 내부 변형도 같은 기준으로 재선택** (v1.2 값 이어받기 금지):
  선형 λ ∈ {1, 3, 10}, ens 앙상블 가중 w ∈ {0, 0.25, 0.5, 0.75, 1},
  GBM 라운드는 그룹 OOF MSE로 타깃별 선택 (격자 100~1600).

## 판정과 정직한 주석

- 1~3위 차이(0.0013)는 CV 노이즈 범위 안이라 통계적으로 결정적이지 않다.
  **사전 등록한 규칙**(가중 CV 승자 채택, 동률이면 선형 — dev-clean 계보와
  순수 stdlib 레이턴시 우위)에 따라 linear(λ=10)를 채택했다.
- v1.2의 실제 구성(ens w=0.5)이 깨끗한 프로토콜에서 5위로 떨어진 것은
  Dev 재사용이 선택을 왜곡했다는 감사 결론의 실증이다.
- 이 표의 수치는 그룹-fold CV 추정치로, 공개 Dev 점수와 직접 비교할 수
  없다 (분포·누수 조건이 다름).

## 후속 조치

- 최종 학습·아티팩트: `analysis/train_linear.py` →
  `src/ossp_router/resources/learned-router.v1.json` (1.11 MB), 런타임 표본
  대조 최대 오차 1.8e-15.
- 배분 tie-break를 문항 위치 인덱스에서 예측값 튜플(내용 유도)로 교체 —
  ID·순서 셔플 점검 대응. 캘리브레이션 시점 배분과의 동치성을 fitted×3 +
  15 fold×3 = 48건 전수 비교로 확인 (불일치 0건).
- 컨테이너 재검증: 3-tier PASS, tier당 5.4초 (ens 대비 2.6배 개선),
  이미지 내 필수 파일 존재 확인.

## Dev 최종 게이트 (2026-08-13, 1회 실행 후 동결)

네트워크 차단 컨테이너(`--network none`)에서 dev 3-tier 실행 후 공식
self-check로 채점했다. **이 실행이 v1.3 개발에서 Dev를 사용한 유일한
평가이며, 이후 라우터 코드·아티팩트·설정은 변경하지 않는다.**

| tier | 점수 | 실현 예산비 | 판정 |
|---|---|---|---|
| fast | 0.6460 | 1.170 / 1.25 (93.6%) | 통과 |
| balanced | 0.6901 | 1.731 / 2.0 (86.5%) | 통과 |
| premium | 0.7017 | 2.145 / 4.0 (53.6%) | 통과 |
| **final** | **0.6759** | 전 tier 한도 내 | **유효 제출** |

주석 (정직한 해석):

- 참고: train self-check(적합 데이터 재예측, 낙관치)는 0.6891.
- v1.2의 dev 0.6920과의 비교는 무의미하다 — 그 수치는 Dev로 선택을
  튜닝한 뒤의 측정이라 낙관 편향이 있고, 이번 0.6759는 Dev 미접촉
  개발의 단 1회 측정치다.
- premium 사용률(53.6%)이 CV 최악치(87%)보다 크게 낮다 — dev의 문항
  구성이 train보다 저비용 방향이라는 뜻으로, 보수적 β·margin이 dev에선
  점수를 다소 남겼지만 이는 비공개 분포 이동에 대한 의도된 보험이다.
- Dev 사용 이력: v1.2까지는 감사 기준 10회 이상이 선택에 개입(오염);
  v1.3 개발 주기에서는 위 게이트 1회가 전부다.

## 반사실 실측 — "v1.2를 dev 없이 만들었다면?" (2026-08-13, 회고 분석)

v1.2의 dev 0.6920에서 오염(낙관 편향)의 크기를 실측했다.
`analysis/counterfactual_ens.py`: 재대결이 dev-clean으로 재선택해 둔 ens
구성을 전체 train으로 적합해 dev에 적용, 공식 self-check로 채점.
**이 dev 평가 2회는 회고 기록 전용이며 어떤 선택의 근거로도 쓰지 않는다**
(v1.3 무접촉 — 실행 전후 아티팩트 sha256 동일·테스트 통과 확인).

| 구성 | dev final | tier (fast/bal/prem) | 예산 |
|---|---|---|---|
| v1.2 실측 (dev 오염) | 0.6920 | 0.6509 / 0.7017 / 0.7372 | 통과 |
| **반사실 ens(w=0.5)** — v1.2 구성, dev-clean 캘리브레이션 | **0.6813** | 0.6542 / 0.6914 / 0.7071 | 통과 (93%/81%/54%) |
| 반사실 ens(w=1.0) — train CV가 골랐을 ens | 0.6764 | 0.6454 / 0.6798 / 0.7142 | 통과 (88%/71%/56%) |
| v1.3 linear (게이트) | 0.6759 | 0.6460 / 0.6901 / 0.7017 | 통과 (94%/87%/54%) |

해석 (정직하게):

- **오염 크기 ≈ 0.0107** (0.6920 − 0.6813). v1.2가 dev 재사용으로 얻은
  점수의 약 1.1pp는 허상이었다. dev-clean 계열의 정직한 수준은 0.68 안팎.
- 반사실 w=0.5의 캘리브레이션(β·margin)은 우리 그룹-fold 프로토콜 산출값
  이므로, "당시 팀이 dev 없이 정했을 마진"과 완전히 같지는 않다 — 방어
  가능한 최근접 반사실로 읽을 것.
- **주의: dev에서는 w=0.5(0.6813) > w=1.0(0.6764) ≈ linear(0.6759)로,
  train CV 순위(linear > w1.0 > w0.5)가 뒤집힌다.** 이것이 "차이가 노이즈
  범위"의 실제 모습이다 — 세 평가셋(CV/dev/비공개)마다 근소 동률 후보들의
  순서는 뒤바뀔 수 있다. 이 수치를 근거로 w=0.5로 갈아타면 그것이 곧
  dev 오염의 재발이므로, 사전 등록 규칙(train CV 승자 채택)을 유지한다.
- 예산은 세 구성 모두 dev에서 통과 — "dev 없이 갔어도 0점은 아니었다".

## v1.4 후보 실험 — 전 경로 게이트 미달, v1.3 확정 (2026-08-13)

성능 향상 후보 3경로를 사전 등록 게이트(train-only, dev 사용 금지,
build/v14/gates.md에 실행 전 고정)로 순차 검증했다. 결과:

| 경로 | 내용 | 게이트 | 실측 | 판정 |
|---|---|---|---|---|
| 1 | train+dev 재적합 | 학습곡선 마지막 구간 Δ ≥ +0.003 | 704→1,056→1,408문항에서 0.6526→0.6528→0.6553 (Δ+0.0025) | 미달 |
| 4 | 입력/출력 분리 비용 예측 | ΔCV ≥ +0.004 | 0.6555 (Δ+0.0002) — 합성 σ 개선 −2~−7%뿐, think 출력 길이가 지배 | 미달 |
| 3 | 이종 특징 점수 앙상블 (linear×GBM-diff) | ΔCV ≥ +0.004 | w=0.5에서 0.6587 (Δ+0.0034) | 미달 |
| 통합 | 최종 후보 ≥ 0.6613 | — | 채택분 없음 | **전량 폐기** |

해석: 세 경로 모두 **양(+)이지만 노이즈 문턱 아래**의 이득 — 데이터 2배가
+0.27pp, 비용 모델 개선이 +0.02pp, 앙상블이 +0.34pp. 남은 개선 여지가
구조적으로 소진됐다는 2×2 분해·문헌(Routing Plateau)의 진단과 일치한다.
v1.3은 실행 전후 무결성 확인(아티팩트 sha 동일·src 무변경·테스트 271 통과)
으로 그대로 유지되며, 이후 작업은 제출 절차·보고서로 전환한다.
